OrchDelay

A responsorial delay — buffers a captured phrase and fires it back once, N bars later, optionally transformed. Not a fixed chain position: an insert you place wherever a call-and-response echo is wanted.
MIDI-FX · flexible insert live Odly

29 real parameters, one static view — big enough that this guide switches from one marker per control to one marker per region, with full tables underneath carrying the exhaustive detail. Live notes are captured into a buffer and echoed back exactly once (no looping/feedback), optionally transposed, retrograded, inverted, rotated, truncated, transformed by M7, time-stretched, or interval-scaled — either an explicit manual choice or a seeded, phrase-content-aware proposal. A 4-slot memory system (3 local banks + phrases received from other OrchDelay instances) lets it echo something other than just the most recent phrase, on demand or entirely on its own clock.

1
Bypass
bypass
Passes MIDI straight through and drains any held/pending material — the hard reset. Every other control on this page is inert while this is on.
2
Capture Mode
captureMode
How a live note relates to an echo already sounding. Replace (default) fully swallows live input — only the delayed echo sounds. Overlay lets live playing continue underneath an echo. Duck thins live notes outside the echo's own current pitch range. The live note is ALWAYS still captured for its own future echo regardless of this setting.
3
Hold, Overlap & Phrase Boundaries
holdBars · holdBarsRandom · overlapMode · phraseGapBeats
Hold Bars is the core "how far in the future" control — 0 is a dedicated pause-capturing state, not a random outcome (Random Hold Bars never draws it). Overlap Mode governs what happens when a due echo collides with one still sounding: Overlap fires anyway (piano-friendly), Wait holds it back and shifts its whole schedule forward once clear, Skip discards it. Phrase Gap is the silence threshold that closes a captured phrase.
4
Phrase Quality & Memory Recall
minimumInterest · callbackProbability · autonomousFireBars
Minimum Interest gates weak captures (default 0% = every phrase always echoes). Callback Probability occasionally echoes an OLDER phrase from Active Bank instead of the one that just closed. Autonomous Fire lets the device free-run from Active Bank on its own "every N bars" clock, entirely independent of new incoming MIDI — deliberately orthogonal to Hold Bars' own pause state.
5
Multi-Bank Memory
captureBank · activeBank · recencyBias
3 independent local banks (A/B/C). Capture Bank picks which one newly-closed phrases land in; Active Bank (A/B/C/Remote) picks which one Callback Probability and Autonomous Fire draw FROM — deliberately decoupled, so a new bank can build up fresh material while a different one keeps playing. Clear Bank empties whichever bank Capture Bank currently points to. Recency Bias (0% default) biases the pool draw toward more recently-captured entries instead of a flat uniform pick. Full detail in §03.
6
Instance Seed
instanceSeed
This instance's own hash key for every seeded draw in the plugin — transform choice, every Random toggle, every pool pick. Deterministic and reload-stable: the same seed always reproduces the same sequence of choices. Randomize writes a fresh value through the normal parameter path (undoable, saved in state).
7
Restlessness & Transform Choice
restlessness · contentAwareWeighting · manualTransform
Transform is the manual override — any explicit choice always wins outright. Left on Follow Restlessness, the Restlessness slider is the probability of proposing a non-verbatim transform per phrase (0% = always verbatim). Content-Aware Weighting (default ON) biases WHICH transform gets picked by the phrase's own density/pitch-spread/note-count instead of a flat 1-in-8 chance.
8
Transform Amounts
transposeSemitones · rotationSteps · lengthPercent · stretchPercent · intervalScalePercent (+ each own Random)
The amount used whenever each transform is active, whether reached manually or via Follow Restlessness. Stretch additionally has Quantize (snaps to a notation-friendly ratio vocabulary instead of an arbitrary percentage). Full table in §02.
9
Cross-Instance Broadcast
linkHub · broadcastChannel · listenChannel
Lets one instance's captured phrases feed another instance's Remote bank directly — in-process, no MIDI cable needed between tracks. Broadcast Hub elects this instance as the shared relay (exactly one per rig). Broadcast Channel publishes captured phrases; Listen Channel receives them from other instances into Remote. Clear Remote empties the Remote bank specifically. Full setup recipe in §04.
10
Status Line
Session-lifetime counters (reset only on transport prepare), not just live state — pending/captured/closed/fired/skipped counts, the last scheduled-vs-reached ppq, the last resolved transform choice, phrase-quality/callback/autofire counters, and the link's own mode (hub / hub(busy) / client(ok) / client(--)) plus a running count of phrases received from other instances.
Real capture of the Standalone build, default state (no host transport, hence the inactive status line).
02

Transform Vocabulary

9 real transforms plus "Follow Restlessness" (a proposal, not a transform itself). All operate directly on the buffered note data — OrchDelay never talks CC-to-MPL, it reimplements the math itself. Two deliberate divergences from MPL's own vocabulary: Inversion mirrors around the phrase's own first/anchor note (not a fixed axis — keeps an echo in the register the player was actually in), and Retrograde is a true whole-phrase time reversal (not a step-grid read-position reversal, which has no meaning for a real-timestamp phrase).

TransformAmount paramRangeWhat it does
None——Verbatim echo, unchanged.
TransposetransposeSemitones-48…48Fixed pitch shift, clamped to 0-127.
Retrograde——Whole-phrase time reversal around its own midpoint, each note's own duration preserved.
Inversion——Pitch-axis mirror around the phrase's own first/anchor note.
RotationrotationSteps-16…16Cyclic reassignment of which captured note's pitch/velocity/channel sounds at each onset slot; wraps to the phrase's own note count.
LengthlengthPercent1…100%Truncates to the first N% of notes by onset order — note count only, never rescales timing.
M7——Pitch-class ×7 mod 12, octave preserved — a pure per-note operation.
StretchstretchPercent (+ Quantize)25…400%Proportional time-stretch around the phrase's own start. Quantize restricts the actual ratio used to a notation-friendly vocabulary (25/33.3/50/66.7/75/100/133.3/150/200/300/400%) instead of an arbitrary in-between value.
IntervalintervalScalePercent0…300%Scales every interval from the phrase's own anchor note — >100% widens the melodic shape's leaps, <100% narrows them. Defaults to 150% so picking it is immediately audible.

Transpose, Rotation, Length, Stretch, and Interval each have their own Random toggle — drawn deterministically per phrase from Instance Seed + phrase count (reload-stable, never a bare RNG). Transpose/Rotation draw a symmetric range around 0; Length uses its own slider as a ceiling (no negative meaning); Stretch/Interval draw from [100%, slider] on whichever side of 100 the slider sits, since their own neutral point is 100%, not 0.

03

Multi-Bank Memory & Recency

A development-section workflow: build up new material in one bank while a different one keeps playing, then switch over. Callback Probability and Autonomous Fire are the only two consumers of the pool, and they always share the SAME Active Bank — splitting them would let the pool a track is "currently developing from" silently fork with no musical rationale.

ControlRangeRole
Capture BankA · B · CWhere a newly-closed phrase gets written. Never Remote — that bank is populated exclusively by incoming broadcasts.
Active BankA · B · C · RemoteWhere Callback Probability AND Autonomous Fire both read from. Switch this to bring a different bank's material into play without touching what's currently being captured.
Clear BankbuttonEmpties whichever bank Capture Bank currently points to.
Recency Bias0–100%0% (default) = flat uniform pick across the whole pool, exactly the original behavior. Above 0%, the draw weights pool index i as (i+1)^exponent (exponent climbing 0→4) — increasingly favoring the newest few entries.

Each bank holds the most-recent 8 phrases actually PLAYED (never a callback substitution itself), oldest evicted first once full.

04

Cross-Instance Broadcast

Lets phrase material cross between OrchDelay instances directly, in-process, over a local loopback relay — no MIDI cable between tracks. Every instance is symmetric: it can publish and/or subscribe at once, regardless of which one happens to run the shared relay. Absolute host ppq needs no translation crossing instances, since every instance already reads the same transport — this is what makes direct pool-sharing tractable at all.

Setup: 1 Hub + N Listeners
  1. On the source instance: turn Broadcast Hub ON. Exactly one instance in the whole project should have this on — it opens the shared relay.
  2. Set its Broadcast Channel to any number 1–8. Feed it MIDI as usual; every phrase it captures now also publishes on that channel.
  3. On each listener instance: leave Broadcast Hub OFF. No MIDI input is required.
  4. Set Listen Channel to the same number as the Hub's Broadcast Channel.
  5. Set Active Bank to Remote.
  6. Set Autonomous Fire (bars) > 0 — this is what actually makes a listener with no local MIDI input audible. Callback Probability only ever evaluates when a phrase closes LOCALLY, so it does nothing on a pure listener.
  7. Check each instance's status line: the Hub should read hub — if it instead reads hub(busy), another instance already has Broadcast Hub on. Listeners should read client(ok) once connected, with remoteIn counting up as phrases arrive.

Multiple independent broadcaster/listener groups can share the same one Hub without cross-talk, each isolated on its own channel number — like several stations sharing one transmission tower. An instance's own Broadcast Channel and Listen Channel are independent, so it can also listen on one channel while publishing what it does with that material on a different one, chaining instances into a relay rather than only a star topology.
